# 微博视频获取与动态画面

`scripts/weibo_video.py` 来自用户提供的桌面脚本，使用 Python 标准库，通过微博访客接口解析视频质量并下载，不依赖原桌面目录，不复制浏览器登录信息或私人下载配置。

```powershell
py -3 -X utf8 "<skill目录>/scripts/weibo_video.py" "https://video.weibo.com/show?fid=1034:视频编号" -q 720 -d "<本次项目>/素材" --quiet
```

可输入 fid、普通微博正文链接或数字 mid。正文接口可能返回 Forbidden；脚本已明确提示该限制。此时在可用浏览器里查看用户话题对应的视频，从实际页面的播放链接读取 fid，再传给脚本。不要猜编号、无休止重试或把受限接口当作无视频。页面若已提供实际视频地址，也可通过浏览器的媒体下载能力获取。签名直链会过期，只把稳定微博链接和 fid 写入来源记录，不写死临时直链。

2026-10-10 实测：正文接口返回 Forbidden，但页面提供的 `1034:5352588867207220` 经脚本成功下载为83.533秒视频。此例是验证记录，后续应提取本次话题的实际编号。

下载后探测并完整解码，检查所选片段的入点、中间和出点；区分回应现场、历史直播、相关报道和网友二创。旧连麦不等于关系证明，历史画面须标“相关直播/过往画面”，不与新声明现场混淆。二创中的指控标题、猜测字幕不能沿用为本次事实；选择干净窗口或换来源。原音与新口播冲突时不用原音。

用户希望尽量保持画面动态、增加内容：视频正常播放优先于静态截图，配合全景、人物局部、分屏、回应文字卡与简短标注；同一片段的局部切换要有解释职责，不能只为增加切数。普通段落不持续震屏或周期缩放。信息不足时扩展可支持的经过、回应层次和清楚标明的观点讨论，不能虚构反转、处罚、关系或网友共识。
