# 事件类视频默认制作流程

用户已认可“先选关键素材、再写旁白串联”的成片方式，今后事件类默认采用。保留尖嗓快语速、动态表情包和关键原声关闭BGM的组合；不固定约62秒、某个事件、特定表情编号或原声数量。普通制作无需再逐步征求批准。

## 1. 素材选择先于旁白

获取并检查实际素材，转写或核对候选发言的上下文。先在项目保存 `素材选择记录.json` 或同等简短记录，再写稿或合成TTS。记录候选的来源、原始入出点、承载的信息、人物/报道/旧直播/文字材料性质、已核实的时间与回应对象，以及选用或排除原因。无法确认的关系明确记为未知，不用文件排列顺序推断事件顺序。

优先选择有信息贡献的关键发言、真正回应问题的原文，以及必要背景片段。已取得片段不是完整直播：只能称保留该片段，不冒称完整上下文；缺失上下文影响理解时换材料或缩减结论。不要为了原声数量选择另一条报道的重复读稿。

## 2. 旁白连接材料

原素材承担具体发言和回应，旁白只补充背景、来源归属和必要过渡。每个信息点选择一个主要表达载体；原声前不先念完其结论，结束后不再复述。同步忠实字幕或旁白对原帖的一次解释可以保留，不能之后再接报道重复读稿。

已核实的事件关系可自然串联；没有依据的先后或回应关系不用“随后/因此/对此回应”。可用“另有一份发文”“再看这份回应”表示观看顺序，但整个声画组合也不能暗示虚假的事件关系。具体底线按 editing-packaging.md 执行。

## 3. 声画制作

- 旁白默认沿用本机已授权且已认可的复刻音色，加尖嗓快语速：音高1.30倍、整体语速1.35倍。可复用本机语音配置；新安装须核实配置实际可用，缺失时说明缺口，不把通用音色冒称已认可音色。密钥、账号配置和个人录音不随公共仓库发布。
- 已验证的配音后处理链：`aresample=48000,asetrate=48000*1.3,aresample=48000,atempo=1.0384615,highpass=f=100,equalizer=f=2800:t=q:w=1:g=2`，之后单独统一响度。只处理旁白，不处理原声或BGM；已处理音轨不要再次叠加同样变调变速。
- 关键原声段旁白完全退出，添加的BGM为零，提示音避开讲话；原声保持原速原音高，只作必要的响度调整。按完整语义剪切并给首尾留余量，音乐恢复避开尾句。记录静音区间并核查最终混音。
- 优先真实动态视频，声明/原帖承担文字信息时留足阅读时间。动态表情包按实际帧时长播放，放在引导、过渡或停顿处，不盖住关键发言、不拼成当事人的真实反应。表情数量随内容决定。
- 主体画面、必要字幕、简短来源标注为主要层次，默认不放重复摘要卡、流程条与章节编号。开场短放大和大字幕可保留，普通段落不持续抖动；随机参考模板也要删掉不必要的装饰。

## 4. 内容与成片验收

先对照源材料检查关键语义、时间顺序和回应对象，再看整片是否造成实质性误解或重复转述。核对关键原声没有混入TTS/添加BGM，也没有变速变调；必要时与源轨做时间及波形对比。仅有转写、抽帧或相关性指标不能冒称人工完整听审。

按 production-checks.md 检查解码、字幕、主体裁切和音频峰值。保存素材选择记录、口播、字幕、时间线及可复用工程，并根据最终内容生成发布文案和标签。一次事件的源素材与测试成片保留在项目内，不作为公共skill默认资产上传。
